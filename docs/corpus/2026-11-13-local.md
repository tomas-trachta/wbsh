# Real-world corpus, 2026-11-13, local

**wbsh sourced 275 of 1,034 runs cleanly (26.6 %); Git Bash 969 of 1,034
(93.7 %) on the same files, same machine, same day.** Two parser bugs
account for 724 of wbsh's 759 failures (see [Causes](#causes)); with those
fixed wbsh would be within a few dozen runs of Git Bash.

Produced with [`tools/corpus/run.py`](../../tools/corpus/README.md) and the
pinned [`manifest.json`](../../tools/corpus/manifest.json):

```sh
python -I tools/corpus/run.py --shell wbsh=wbsh.exe \
    --shell "git-bash=C:/Program Files/Git/bin/bash.exe" \
    --clone-root C:/scratch/corpus-src --low-priority --jobs 2 \
    --markdown snapshot.md --json corpus.json
```

- wbsh: 1.1.1, `x64/Release/wbsh.exe` built 2026-11-13 23:07 from 0d0f1b6
  plus the uncommitted `feat/drop-in-roadmap` work (the same build as
  [compat-ledger.md](../compat-ledger.md)).
- Reference: Git Bash from Git for Windows 2.35.1 (GNU bash 4.4.23).
- Machine: Windows 10 22H2 (19045), Ryzen 7 5800H, 16 GB; 2 runs in
  parallel at below-normal priority.
- A run is one entry file sourced by one shell in one mode. Top-level entry
  points (the frameworks' main files, nvm, sdkman, asdf, git's completion)
  run in a script and in an interactive shell; the 1,018 plugins, themes,
  aliases and completions run interactively after their framework, as a
  user's `~/.bashrc` would load them. "Sourced cleanly" means exit status 0,
  nothing on stderr, and the entry's check passed.
- starship, zoxide, direnv and fzf were not installed on this machine, so
  their generated init scripts were skipped.

## Causes

| runs | cause | reproducer |
| ---: | --- | --- |
| 541 | a `[[ ... ]]` whose operands continue on the next line after `&&` (`[[ a &&` newline `-z "" ]]`) is a parse error, so `bash_completion` and bash-it's `githelpers.theme.bash` stop loading, and every completion or plugin that needs them fails | [B12](../compat-ledger.md#shell-bugs-found) |
| 183 | `eval -- "a=(...)"`: wbsh treats `--` as a word, which breaks oh-my-bash's `_omb_util_glob_expand` and with it every oh-my-bash load | [B28](../compat-ledger.md#shell-bugs-found) |
| 1 | `shopt -qo name` (clustered options) rejected | [B29](../compat-ledger.md#shell-bugs-found) |
| 1 | `$(( ... ))` in liquidprompt's theme: `0 1: syntax error in expression` | not reduced yet |

Most of the remaining failures, under both shells, are plugins for tools
that are not installed (`pg_config`, `chruby`, `fasd`, `tmux`, ...) or that
exit 1 by design when their tool is missing. bash-it's symlink handling
([B14](../compat-ledger.md#shell-bugs-found)) did not show up in this run
because each run gets a private copy of the framework.
