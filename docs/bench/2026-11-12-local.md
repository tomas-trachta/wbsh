# Benchmarks, 2026-11-12, local

Produced with [`tools/bench/bench.py`](../../tools/bench/bench.py):

```sh
python -I tools/bench/bench.py --shell wbsh=wbsh.exe \
    --shell "git-bash=C:/Program Files/Git/bin/bash.exe" \
    --runs 7 --warmup 1 --low-priority --json bench.json --markdown bench.md
```

The run was time-boxed (about two minutes in all), so it uses 7 timed runs
per cell instead of the 30 the roadmap protocol asks for; treat ratios under
about 1.2x as noise. The harness and every shell ran at below-normal priority
on a desktop that was also building and testing, so absolute numbers are on
the slow side. Each cell is the median wall time, with the 90th percentile
beside it and the ratio to wbsh in brackets (above 1 means slower than wbsh).

| case | workload |
| --- | --- |
| `startup` | `wbsh -c true`: process start to exit |
| `function_calls` | 20000 calls of an empty function |
| `arith_loop` | 50000 iterations of `(( x += i ))` |
| `string_append` | 20000 appends of one character |
| `array_fill` | 20000 appends to an indexed array |
| `builtin_pipeline` | 25 runs of `echo \| tr \| cut` (built-in in wbsh, MSYS programs in Git Bash) |
| `external_spawn` | 150 runs of `C:/Windows/System32/hostname.exe` |
| `cmdsubst_loop` | 100 command substitutions `$(echo $i)` |
| `read_loop` | `while read` over a 5000-line file |

## Notes

- Minimums, means and every raw sample are in the JSON the run wrote; the
  medians above are what the harness prints.
- `function_calls` is the closest row (1.15x): it is the one the roadmap's
  Phase 3 already names as the interpreter's weak spot.
- `builtin_pipeline` costs wbsh about 26 ms per three-stage pipeline of
  built-ins, far more than any other per-iteration cost here. It is the
  first place to look for pipeline overhead.
- `external_spawn` is dominated by `CreateProcess`; 20 ms per spawn for wbsh
  against 40 ms for Git Bash.
