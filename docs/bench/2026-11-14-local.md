# Benchmarks, 2026-11-14, local

Produced with [`tools/bench/bench.py`](../../tools/bench/bench.py):

```sh
python -I tools/bench/bench.py --shell wbsh=wbsh.exe \
    --shell "git-bash=C:/Program Files/Git/bin/bash.exe" \
    --runs 10 --warmup 1 --json bench.json --markdown bench.md
```

The run uses 10 timed runs per cell instead of the 30 the roadmap protocol
asks for; treat ratios under about 1.2x as noise. The desktop was also
running another agent's builds and tests, so the two shells were timed
interleaved as usual and the ratios are the numbers to compare. Each cell is
the median wall time, with the 90th percentile beside it and the ratio to
wbsh in brackets (above 1 means slower than wbsh).

## Notes

- Minimums, means and every raw sample are in the JSON the run wrote; the
  medians above are what the harness prints.
- `startup` lost about 9 ms to one call: `$PPID` came from a snapshot of
  every process on the machine. It is now one `NtQueryInformationProcess`
  of the shell itself. A `-c true` start is now within about 1 ms of
  `wbsh --version`, so what is left is process creation, DLL loading and
  teardown.
- `function_calls` is no longer the weak row (1.12x before, 1.79x now):
  FUNCNAME, BASH_SOURCE and BASH_LINENO are edited in place on each call
  instead of rebuilt, a one-element PIPESTATUS is overwritten in place, and
  a plain literal word such as a command name skips brace, tilde, split and
  glob processing.
- `builtin_pipeline`: each element of a pipeline of built-ins was a wbsh
  process of its own. Without job control the first element now runs as a
  subshell inside the shell, as `( ... )` already did, so a three-stage
  pipeline starts two processes instead of three (about 20 ms down to
  about 14 ms per pipeline). It is the first element, not the last, so that
  its writes land in the pipe at once the way a forked bash subshell's do.
- `cmdsubst_loop` spent most of its time creating, reopening and deleting a
  named temp file for every `$(...)`. The capture file is now opened once,
  delete-on-close, and emptied for the next substitution while no other
  process holds it: about 0.8 ms down to about 0.25 ms per substitution.
- `external_spawn` is `CreateProcess` and the wait for the child; the
  environment block the shell builds for each spawn was under 1 % of the
  profile, so it is not cached.
