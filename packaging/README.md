# Package manifests

Generated by `tools/packaging/write-manifests.ps1`; the release workflow
rewrites them for every release and commits the result. Edit the script, not
the files.

| Folder | Package manager | Installs |
| --- | --- | --- |
| `scoop/` | [Scoop](https://scoop.sh) | the portable ZIPs, `wbsh.exe` / `wbshterm.exe` shimmed onto PATH |
| `winget/manifests/` | [winget](https://learn.microsoft.com/windows/package-manager/) | the per-user Inno installers, laid out as in `microsoft/winget-pkgs` |

Each manifest lists every architecture the release ships: x64 and, from the
first release built with ARM64, arm64 (Scoop's `64bit` / `arm64`, winget's
`x64` / `arm64` installers). Older releases list x64 only.

## Scoop

```powershell
scoop install https://raw.githubusercontent.com/tomas-trachta/wbsh/main/packaging/scoop/wbsh.json
scoop install https://raw.githubusercontent.com/tomas-trachta/wbsh/main/packaging/scoop/wbshterm.json
```

Both manifests carry `checkver` and `autoupdate` (hashes from the release's
`SHA256SUMS.txt`), so they can move to a bucket such as `extras` unchanged.

## winget

When the repository has a `WINGET_TOKEN` secret (a classic PAT with
`public_repo` scope), the release workflow opens the pull requests on
`microsoft/winget-pkgs` with `wingetcreate submit`. By hand:

```powershell
winget validate --manifest packaging\winget\manifests\t\TomasTrachta\wbsh\<version>
wingetcreate submit --token <PAT> packaging\winget\manifests\t\TomasTrachta\wbsh\<version>
```

Once merged: `winget install TomasTrachta.wbsh` / `winget install TomasTrachta.wbshterm`.

## Checksums

Every release from now on carries `SHA256SUMS.txt` for all installers and ZIPs.
Once code signing is set up ([docs/signing.md](../docs/signing.md)) the sums
and manifests describe the signed files.
